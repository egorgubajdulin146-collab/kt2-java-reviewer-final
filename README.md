# Сервис назначения ревьюеров — учебный объём КТ2

Задание Авито, осенняя волна 2025:
https://github.com/avito-tech/tech-internship/blob/main/Tech%20Internships/Backend/Backend-trainee-assignment-autumn-2025/Backend-trainee-assignment-autumn-2025.md

Выбран основной сценарий: создать команду, создать PR с 0–2 активными ревьюерами из команды автора, получить PR пользователя. Автор исключается. Хранение в памяти разрешено заданием. Использованы Java 21, JDK HttpServer и Jackson. Spring для этого небольшого объёма не требуется.

## Запуск

JDK 21+ и Maven 3.9+: `mvn package`, затем `java -jar target/reviewer-1.0.jar`.
Проверка: `python3 tests/smoke.py` при запущенном сервере. Тесты требуют пустое хранилище, перед повтором перезапустите сервер.
Контейнер: `docker compose up --build`. Порт 8080. Для старого CLI можно использовать `docker-compose up --build`.
`PORT` меняет порт Java-процесса. GET /health возвращает состояние процесса.

## API

POST /team/add — тело по приложенной openapi.yml.
POST /pullRequest/create — pull_request_id, pull_request_name, author_id.
GET /users/getReview?user_id=u2 — назначения на ревью.
GET /health — проверка доступности.

## Границы и допущения

Merge, переназначение, изменение активности, GET /team/get, статистика и нагрузочные SLI остаются за выбранным объёмом. Поэтому это частичное выполнение тестового задания компании.
Новый team/add обновляет существующего пользователя и его команду. Повторное имя команды отклоняется. Повторный user_id внутри одной команды — ошибка 400. Некорректный запрос не изменяет данные. Проверка и изменение данных защищены одним монитором. Пустое тело или неверные типы дают 400. При недостатке кандидатов назначаются 0 или 1 человек, как требует задание.
После перезапуска данные теряются. Health проверяет процесс, отдельной БД нет. Логи ошибок пишутся в stderr. Для эксплуатации нужны долговременное хранилище, метрики и полноценные проверки готовности.

## Проверка и использование ИИ

tests/smoke.py проверяет HTTP-коды, исключение автора и неактивного участника, 0/1/2 кандидата, дублирование PR и команды, неизвестного пользователя и атомарность валидации.
Codex помогал с подготовкой проекта, ревью и Dockerfile.

В dist/reviewer.jar приложена сборка из исходников. Dockerfile использует этот JAR, поэтому сборка контейнера не скачивает зависимости Maven. После изменения Java-кода пересоберите `mvn package` и выполните `cp target/reviewer-1.0.jar dist/reviewer.jar` перед `docker compose up --build`.
При проверке сборки из исходников внутри контейнера Maven Central вернул HTTP 403 для jackson-core. Локальная Maven-сборка завершилась успешно.
